# CAFE MOCA 럭키드로우

## 현재 지급 규칙

- 1~4등 중 한 가지를 랜덤으로 받습니다.
- 1등 망고산도 5개와 3등 버터떡 25개는 한국 시간 **13:00부터** 추첨됩니다. 2등 베이글 20개는 처음부터 추첨됩니다.
- 4등은 컴포즈커피입니다. 해당 시점 커피가 없으면 협찬품으로 대체됩니다.
- 컴포즈는 2026-09-10 **09:50 / 12:50 / 14:50에 각 35잔, 총 105잔**입니다. 남은 커피는 다음 입고에 더해집니다.
- 협찬품은 별도로 197명분입니다. 최초 결과가 고정되며 중복 요청으로 재고를 다시 차감하지 않습니다.

## DB에서 수량 확인

| 항목 | 위치 | 의미 |
| --- | --- | --- |
| 컴포즈 총 105잔 | `public.lucky_draw_prizes`의 4등 `total_count` | 실제 커피 총량 |
| 컴포즈 미지급 잔 수 | 같은 행의 `remaining_count` | 아직 도착하지 않은 예정 수량도 포함 |
| 현재 지급 가능한 커피 | `moca_lucky_private.coffee_stock(clock_timestamp())` | 현재까지 입고량 − 커피 지급 확정량 |
| 협찬품 총 197명분 | `moca_lucky_private.event_config.sponsor_total` | 커피와 별도인 협찬품 총량 |
| 4등 추첨 횟수 | `moca_lucky_private.fourth_prize_tickets` | 기존 추첨 구성 유지용이며 실물 재고가 아님 |

기존에는 4등 추첨 횟수 147이 컴포즈 수량 칸에 들어가 있었습니다. `supabase/compose_actual_stock.sql`은 추첨 구성을 유지하면서 실제 커피 수량을 105로 분리합니다. 협찬품을 대신 받으면 커피 미지급 수량은 줄지 않습니다.

SQL은 현재 행사 DB에 대한 변경입니다. Supabase 마이그레이션으로 원자적으로 적용하거나, SQL Editor에서 파일 전체를 `begin;` / `commit;`으로 감싸 실행합니다. 기존 결과와 사용한 수량을 보존합니다.

`supabase/verify_compose_stock.sql`은 행사 전 결과가 비어 있을 때 실행하는 회귀 검증입니다. 반드시 파일 전체를 실행하세요. 생성한 가상 참여자와 재고 변경은 모두 롤백됩니다.

```sh
npm ci
npm run dev
npm run build
```
